Parte 1

useState e Imutabilidade

As 2 Regras de Ouro dos Hooks

  • 1. Apenas no nível superior (top level): nunca chame um Hook dentro de if, for ou depois de um return antecipado.
  • 2. Apenas em funções do React: chame somente dentro de componentes React ou de Custom Hooks (use...).
// ❌ ERRADO: se id for vazio, o número de hooks chamados muda!
if (!id) return <Text>Carregando...</Text>;
const [seconds, setSeconds] = useState(0);

// ✅ CORRETO: todos os hooks sempre no topo do componente
const [seconds, setSeconds] = useState(0);
if (!id) return <Text>Carregando...</Text>;

Atualização funcional: prev => ...

O estado não muda instantaneamente na linha seguinte — o React agenda uma nova renderização. Quando o próximo valor depende do anterior, passe uma função:

const [streak, setStreak] = useState(0);

// ❌ Lê o mesmo 'streak' congelado desta renderização
const somarDoisErrado = () => {
  setStreak(streak + 1);
  setStreak(streak + 1); // Resultado: +1 em vez de +2
};

// ✅ Recebe o valor mais recente da fila de atualização
const somarDoisCerto = () => {
  setStreak((prev) => prev + 1);
  setStreak((prev) => prev + 1); // Resultado: +2
};

Imutabilidade em Arrays e Objetos

O React compara a referência antiga com a nova (novo !== antigo). Usar .push() modifica o mesmo array e a tela não re-renderiza.

const [habits, setHabits] = useState<Habit[]>([]);

// ✅ Adicionar item: espalhamento (...)
setHabits((prev) => [...prev, novoHabito]);

// ✅ Atualizar item: .map() devolvendo novo objeto
setHabits((prev) =>
  prev.map((h) => (h.id === id ? { ...h, done: !h.done } : h))
);

// ✅ Remover item: .filter()
setHabits((prev) => prev.filter((h) => h.id !== id));

Parte 2

useEffect e Ciclo de Vida

Sincronizando com o mundo externo

Renderizar deve ser um cálculo puro de props e state. Quando o componente precisa conversar com algo fora do React (timers, sensores, notificações, rede), usamos useEffect:

useEffect(() => {
  // 1. Efeito: executa DEPOIS que a tela foi desenhada
  console.log('Monitorando hábito:', id);

  // 2. Cleanup (opcional): executa antes de re-executar ou ao desmontar
  return () => {
    console.log('Parando monitoramento de:', id);
  };
}, [id]); // 3. Array de dependências

Os 3 modos do array de dependências

SintaxeQuando o efeito rodaExemplo prático
useEffect(fn) (sem array)Após toda renderizaçãoLog de diagnóstico (cuidado!)
useEffect(fn, []) (vazio)Só 1 vez quando a tela montaRegistrar listener de notificação
useEffect(fn, [id])Ao montar + quando id mudarCarregar dados do hábito id

Regra prática: toda variável do componente lida dentro do useEffect deve estar no array de dependências.

Fechando a torneira: função de Cleanup

export default function FocusTimer() {
  const [seconds, setSeconds] = useState(0);
  const [isRunning, setIsRunning] = useState(true);

  useEffect(() => {
    if (!isRunning) return;

    const timerId = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);

    // Roda quando isRunning muda OU quando o usuário sai da tela!
    return () => clearInterval(timerId);
  }, [isRunning]);

  return <Text>Foco: {seconds}s</Text>;
}

Armadilhas clássicas do useEffect

❌ Loop infinito

useEffect(() => {
  // Altera a própria dependência!
  setCount(count + 1);
}, [count]);

✅ Estado derivado sem efeito

// Não use useEffect para calcular
// algo a partir de outro estado:
const concluidos = habits.filter(
  (h) => h.done
).length;

Prop Drilling × Contexto

Com Prop Drilling

  C -->|"prop"| D["HabitCard"]

Com useContext

flowchart TB
  P["ThemeProvider"] -. "useTheme()" .-> D2["HabitCard"]
  P -. "useTheme()" .-> S2["SettingsScreen"]
  P --> B2["TabsLayout"] --> D2

Componentes intermediários não precisam saber que o tema existe.

Criando um Contexto em 3 passos

// src/context/theme-context.tsx
import { createContext, useContext, useState, type PropsWithChildren } from 'react';

type ThemeContextData = { isDark: boolean; toggleTheme: () => void };

// 1. Criar o contexto
const ThemeContext = createContext<ThemeContextData | undefined>(undefined);

// 2. Criar o Provider
export function ThemeProvider({ children }: PropsWithChildren) {
  const [isDark, setIsDark] = useState(false);
  const toggleTheme = () => setIsDark((prev) => !prev);

  return (
    <ThemeContext.Provider value={{ isDark, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

// 3. Criar custom hook para consumo seguro
export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error('useTheme precisa estar dentro de ThemeProvider');
  return ctx;
}

Plugando o Provider no _layout.tsx

// src/app/_layout.tsx
import { Stack } from 'expo-router';
import { ThemeProvider } from '@/context/theme-context';

export default function RootLayout() {
  return (
    <ThemeProvider>
      <Stack />
    </ThemeProvider>
  );
}

// Em qualquer tela (ex: src/app/settings.tsx):
export default function SettingsScreen() {
  const { isDark, toggleTheme } = useTheme();
  return <Switch value={isDark} onValueChange={toggleTheme} />;
}

Quando usar (e quando evitar) useContext

  • ✅ Excelente para: dados que mudam pouco e afetam muitas telas (Tema claro/escuro, Idioma, Usuário logado).
  • ⚠️ Cuidado com: dados que mudam com alta frequência ou objetos gigantes.

Quando o value do Provider muda, todos os componentes que chamam useContext re-renderizam — não há seleção parcial de propriedades.

Parte 4

Estado Global com zustand

Por que Zustand?

Zustand é uma biblioteca leve de gerenciamento de estado global para React e React Native:

  • 🪶 Sem <Provider>: a store existe fora da árvore e é acessada via hook
  • 🎯 Seletores cirúrgicos: só re-renderiza o componente se a fatia selecionada mudar
  • 📦 Estado + Ações juntos: sem reducers complexos nem actions espalhadas
npm install zustand

Criando a Store com create

// src/store/use-habit-store.ts
import { create } from 'zustand';

export type Habit = { id: string; title: string; done: boolean };

type HabitStore = {
  habits: Habit[];
  addHabit: (title: string) => void;
  toggleHabit: (id: string) => void;
  removeHabit: (id: string) => void;
};

export const useHabitStore = create<HabitStore>((set) => ({
  habits: [
    { id: '1', title: 'Beber 2L de água', done: false },
    { id: '2', title: 'Ler 15 páginas', done: true },
  ],
  addHabit: (title) =>
    set((state) => ({
      habits: [...state.habits, { id: Date.now().toString(), title, done: false }],
    })),
  toggleHabit: (id) =>
    set((state) => ({
      habits: state.habits.map((h) => (h.id === id ? { ...h, done: !h.done } : h)),
    })),
  removeHabit: (id) =>
    set((state) => ({
      habits: state.habits.filter((h) => h.id !== id),
    })),
}));

Consumindo a Store com Seletores

// src/app/(tabs)/index.tsx
import { useHabitStore } from '@/store/use-habit-store';

export default function HomeScreen() {
  // ✅ Seletor: assina apenas a propriedade necessária
  const habits = useHabitStore((state) => state.habits);
  const toggleHabit = useHabitStore((state) => state.toggleHabit);

  return (
    <FlatList
      data={habits}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <Pressable onPress={() => toggleHabit(item.id)}>
          <Text>{item.done ? '✅' : '⬜'} {item.title}</Text>
        </Pressable>
      )}
    />
  );
}

Sincronizando Aba Stats e Rota Dinâmica [id]

// src/app/(tabs)/stats.tsx
export default function StatsScreen() {
  const habits = useHabitStore((state) => state.habits);
  const done = habits.filter((h) => h.done).length;
  return <Text>Progresso: {done} / {habits.length} concluídos</Text>;
}

// src/app/habit/[id].tsx
export default function HabitDetailScreen() {
  const { id } = useLocalSearchParams<{ id: string }>();
  const habit = useHabitStore((state) => state.habits.find((h) => h.id === id));
  const toggleHabit = useHabitStore((state) => state.toggleHabit);

  if (!habit) return <Text>Hábito não encontrado</Text>;
  return (
    <Pressable onPress={() => toggleHabit(habit.id)}>
      <Text>{habit.title}: {habit.done ? 'Concluído ✅' : 'Pendente ⬜'}</Text>
    </Pressable>
  );
}

Parte 5

Persistência Local em Disco

Memória RAM × Disco do Aparelho

Até agora, useState, useContext e zustand vivem apenas na memória RAM. Quando o usuário fecha o app, tudo volta para a estaca zero.

  • 🔑 AsyncStorage: dicionário chave-valor assíncrono em JSON (preferências, flags, listas leves)
  • 🔄 Middleware persist do Zustand: sincroniza a store do Zustand com o AsyncStorage automaticamente
  • 🗄️ expo-sqlite: banco de dados SQL relacional completo para grandes volumes e filtros complexos

AsyncStorage: chave e valor assíncrono

npx expo install @react-native-async-storage/async-storage

Guarda apenas string — use JSON.stringify ao salvar e JSON.parse ao ler:

import AsyncStorage from '@react-native-async-storage/async-storage';

// Salvar preferência no disco
export async function salvarTema(isDark: boolean) {
  await AsyncStorage.setItem('@habits:theme', JSON.stringify(isDark));
}

// Ler preferência ao abrir o app (ex: num useEffect com [])
export async function carregarTema(): Promise<boolean> {
  const valor = await AsyncStorage.getItem('@habits:theme');
  return valor !== null ? JSON.parse(valor) : false;
}

Middleware persist do Zustand

Em vez de chamar AsyncStorage manualmente em cada ação, o middleware persist grava e recarrega (hidrata) a store sozinho:

// src/store/use-habit-store.ts
import AsyncStorage from '@react-native-async-storage/async-storage';
import { create } from 'zustand';
import { createJSONStorage, persist } from 'zustand/middleware';

export const useHabitStore = create<HabitStore>()(
  persist(
    (set) => ({
      habits: [],
      addHabit: (title) =>
        set((s) => ({ habits: [...s.habits, { id: Date.now().toString(), title, done: false }] })),
      toggleHabit: (id) =>
        set((s) => ({ habits: s.habits.map((h) => (h.id === id ? { ...h, done: !h.done } : h)) })),
      removeHabit: (id) =>
        set((s) => ({ habits: s.habits.filter((h) => h.id !== id) })),
    }),
    {
      name: '@habits:store', // Chave no AsyncStorage
      storage: createJSONStorage(() => AsyncStorage),
    }
  )
);

Atenção ao currying do TypeScript: create<HabitStore>()(persist(...)).

expo-sqlite: banco relacional no celular

npx expo install expo-sqlite
import * as SQLite from 'expo-sqlite';

const db = await SQLite.openDatabaseAsync('habits.db');

// 1. Criar tabela (execAsync)
await db.execAsync(`
  CREATE TABLE IF NOT EXISTS habits (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    done INTEGER DEFAULT 0
  );
`);

// 2. Inserir ou atualizar com placeholders '?' (runAsync)
await db.runAsync('INSERT INTO habits (title, done) VALUES (?, ?)', 'Beber água', 0);

// 3. Consultar linhas tipadas (getAllAsync)
const pendentes = await db.getAllAsync<{ id: number; title: string; done: number }>(
  'SELECT * FROM habits WHERE done = ? ORDER BY id DESC',
  0
);
