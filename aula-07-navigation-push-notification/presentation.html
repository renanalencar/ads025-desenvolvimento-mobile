Parte 1

Rotas dinâmicas

A gaveta de fotos

Uma rota dinâmica é uma tela cujo conteúdo depende de um parâmetro — em vez de /sobre, você tem /habit/5 e /habit/42 abrindo a mesma tela com dados diferentes.

  • 📁 Rota estática: sempre a mesma coisa — /sobre, /configuracoes
  • 🗂️ Rota dinâmica: detalhe de item, edição, busca — /habit/[id]
Analogia: cada hábito é como uma pasta dentro de um álbum. A pasta é a mesma ([id]), mas dentro dela tem foto diferente dependendo de qual ID você abrir.

Sintaxe: colchetes são especiais

ArquivoAceita qual URLParâmetros
habit/[id].tsx/habit/123{ id: "123" }
habit/[id]/edit.tsx/habit/123/edit{ id: "123" }
[...rest].tsx/qualquer/coisa{ rest: [...] }

Convenção: minúsculas com hífen — [habit-id].tsx, não [HabitId].tsx.

Navegar para rota dinâmica

// Link com objeto
<Link href={{ pathname: '/habit/[id]', params: { id: '5' } }}>
  Ver hábito 5
</Link>

// router.push com objeto
router.push({
  pathname: '/habit/[id]',
  params: { id: '5' }
})

O parâmetro entra via params, sempre string.

Ler os parâmetros

import { useLocalSearchParams } from 'expo-router';

export default function HabitDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();

  useEffect(() => {
    fetchHabit(id);
  }, [id]);

  return <Text>Hábito: {id}</Text>;
}

useLocalSearchParams() é o padrão. useGlobalSearchParams() é raro.

Remount vs. atualização

router.push({ pathname: '/habit/[id]', params: { id: '5' } });
router.push({ pathname: '/habit/[id]', params: { id: '6' } });
// A segunda chamada REMONTA o componente

Consequência: a lista no fundo é destruída. Voltar com back() a traz de volta.

Parte 2

Tabs

Abas lado a lado, não pilha

Tabs é um navegador onde várias telas convivem num menu em abas — como no Instagram: Home, Explorar, Perfil. Diferente de Stack, Tabs não empilha.

  • Cada aba é uma tela independente, com seu próprio scroll e estado
  • Trocar de aba preserva o estado — como as abas do navegador

Tabs — estrutura de pastas

src/app/
  (tabs)/
    _layout.tsx        ← Define as abas
    index.tsx          ← Aba 1
    search.tsx         ← Aba 2
    profile.tsx        ← Aba 3

A pasta (tabs) com parênteses não vira rota — é transparente.

Tabs — implementação

// app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';

export default function TabLayout() {
  return (
    <Tabs screenOptions={{ tabBarActiveTintColor: '#007AFF' }}>
      <Tabs.Screen
        name="index"
        options={{
          title: 'Home',
          tabBarIcon: ({ color }) => <Icon name="home" color={color} />
        }}
      />
      <Tabs.Screen name="settings" options={{ title: 'Settings' }} />
    </Tabs>
  );
}

Parte 3

Drawer

A gaveta lateral

Drawer é um menu lateral que desliza de fora da tela. Diferente de Stack e Tabs, o Drawer é modal — quando aberto, flutua por cima.

  • iOS: arrastar da borda esquerda
  • Android: deslizar de lado ou botão no cabeçalho

Drawer — instalação obrigatória

npx expo install react-native-reanimated \
  react-native-worklets react-native-gesture-handler

Sem essas 3 libs, o Drawer não funciona. Instalar antes da aula.

Drawer — implementação

// app/_layout.tsx
import { Drawer } from 'expo-router/drawer';

export default function DrawerLayout() {
  return (
    <Drawer screenOptions={{ drawerActiveTintColor: '#007AFF' }}>
      <Drawer.Screen name="(tabs)" options={{ drawerLabel: 'Home' }} />
      <Drawer.Screen name="about" options={{ drawerLabel: 'About' }} />
      <Drawer.Screen name="settings" options={{ drawerLabel: 'Settings' }} />
    </Drawer>
  );
}

Abrir o drawer por código

import { useNavigation } from '@react-navigation/native';

const navigation = useNavigation();

<Pressable onPress={() => navigation.openDrawer()}>
  <Text>☰ Menu</Text>
</Pressable>

Import de @react-navigation/native, não de expo-router.

Parte 4

Push Notifications

Notificações — o fluxo completo

sequenceDiagram
  participant App
  participant OS
  participant Server
  App->>OS: "Peco permissao"
  OS->>App: "Concedido/Negado"
  App->>App: "Pego token"
  App->>Server: "Envio token pro servidor"
  Server->>OS: "Envio notificacao"
  OS->>App: "Notificacao chegou"

Hoje: até "Notificação chegou". Push remoto é depois.

Permissão

import * as Notifications from 'expo-notifications';

const { status } = await Notifications.requestPermissionsAsync();
if (status !== 'granted') {
  console.log('Permissão negada');
  return;
}

iOS: dialog "O app gostaria de enviar notificações. Permitir?"

Pegar o token

import Constants from 'expo-constants';

const projectId = Constants?.expoConfig?.extra?.eas?.projectId;
const token = await Notifications.getExpoPushTokenAsync({ projectId });
console.log('Token:', token.data);
// Envie para o backend aqui

Token identifica o dispositivo. Único por instalação.

Comportamento em foreground

Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldPlaySound: true,
    shouldSetBadge: true,
    shouldShowBanner: true,
  }),
});

Sem isso: notificação chega mas não mostra com app aberto.

Listeners e agendamento local

Notifications.addNotificationResponseReceivedListener((response) => {
  // Usuário tocou — navegar para a tela certa
  router.push('/habit/' + response.notification.request.content.data.habitId);
});

await Notifications.scheduleNotificationAsync({
  content: { title: 'Hora do hábito!', data: { habitId: '5' } },
  trigger: { seconds: 5 },
});
